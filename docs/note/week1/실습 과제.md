## Action Quest

### 이번 주 목표

확인된 제품 약속과 아직 답이 필요한 질문을 분리하고, W2에서 테스트와 코드로 옮길 설계 기록을 만듭니다. 제품 코드는 변경하지 않습니다.

### 시작하기 전에

JDK 21을 사용하고 저장소의 Gradle wrapper로 실행합니다. 테스트가 container를 시작하는 환경이면 Docker도 먼저 실행합니다.

Java와 Kotlin 중 하나를 선택해 저장소 root를 엽니다. 처음 받는다면 해당 block을 실행하고, 이미 clone했다면 `git rev-parse HEAD`로 현재 revision만 확인합니다.

**Java**

```bash
git clone https://github.com/loopers-labs/loop-pack-be-l2-vol5-java.git
cd loop-pack-be-l2-vol5-java
git checkout 313abe5821abd4bde6b29e2a16a849177cff01e2
git rev-parse HEAD
```

**Kotlin**

```bash
git clone https://github.com/loopers-labs/loop-pack-be-l2-vol5-kotlin.git
cd loop-pack-be-l2-vol5-kotlin
git checkout 807c3f87114d2bef4fcfb27333df93d5706d4fe2
git rev-parse HEAD
```

허용 변경은 `../../design/week1`와 선택한 언어의 `ContractClassificationTest`뿐입니다. `apps/commerce-api/src/main/**`, 기존 test, build, dependency는 바꾸지 않습니다.

**읽을 위치**

- Java: `apps/commerce-api/src/main/java/com/loopers/interfaces/api/example/ExampleV1ApiSpec.java`, `ExampleV1Controller.java`, `../ApiControllerAdvice.java`, `../ApiResponse.java`
- Java: `apps/commerce-api/src/test/java/com/loopers/interfaces/api/ExampleV1ApiE2ETest.java`
- Kotlin: 같은 상대 경로의 `src/main/kotlin`, `src/test/kotlin`, `.kt` 파일

**이번 주에 정해진 입력**

- 확인된 제품 약속: 구매자는 주문 확정 전에 보유 쿠폰을 적용할 수 있고, 확정된 할인 금액은 이후에도 유지됩니다.
- 실습 장면의 조건: 쿠폰 한 장, `finalAmount = originalAmount - discountAmount`, 같은 요청의 결과 재사용, 요청 시작 시각의 만료 판단
- 학습자가 정할 것: 실제 제품에 물어볼 질문, API 오류 의미, 규칙을 맡을 책임과 내부 경계, 비교할 대안

### 실행 항목

- [ ]  **기존 테스트의 세 경우를 읽고 실행한다**

`ExampleV1ApiE2ETest`가 확인하는 정상 숫자, 숫자가 아닌 ID인 `나나`, 존재하지 않는 숫자 ID의 예상 상태를 먼저 적습니다. 테스트를 실행해 starter 기준선을 확인하되, 이 테스트가 미매핑 URL이나 응답 body 전체를 출력한다고 가정하지 않습니다.

```bash
./gradlew :apps:commerce-api:test --tests '*ExampleV1ApiE2ETest'
```

- [ ]  **네 입력을 관찰 테스트로 작성한다**

선택한 언어에 `ContractClassificationTest`를 추가해 정상 숫자, `abc`, 존재하지 않는 숫자 ID, 미매핑 URL을 실제로 요청합니다. 각 입력의 HTTP status, `meta.result`, error code, `data` 유무를 assertion하고 같은 값을 설계 문서의 단일 표에 기록합니다. 별도 curl 로그는 제출하지 않습니다.

```bash
./gradlew :apps:commerce-api:test --tests 'com.loopers.interfaces.api.ContractClassificationTest'
```

- [ ]  **기준 문장을 사실과 질문으로 나눈다**

`../../design/week1`에 기준 문장과 출처, 확인된 사실 2개, 실습 장면의 조건 4개, 실제 제품 담당자에게 물을 질문 3~5개를 적습니다. 각 질문에는 답에 따라 달라지는 사용자 응답, 저장 데이터, 권한 중 하나를 연결합니다.

도구가 제안한 내용은 제품 정책으로 바로 채택하지 않습니다. 출처가 없으면 `보류` 또는 `거절`로 표시하고 이유를 적습니다. 제안이 없었다면 `해당 없음`이라고 씁니다.

- [ ]  **여섯 규칙을 반례와 연결한다**

W2에서 같은 뜻으로 사용할 `INV-001..006`을 자신의 문장으로 작성합니다. 각 행에는 `규칙 ID / 출처 구분(제품 약속·실습 조건·제품 질문) / 깨지는 입력 / 기대 결과 / 책임 후보`를 둡니다. 소유권, 금액 경계, 확정 결과 보존, 중복 요청, 만료 경계를 포함하고 각 규칙에 반례 하나를 연결합니다.

- [ ]  **외부 계약과 내부 경계를 선택한다**

method·path·사용자 식별·request·success·error meaning을 정합니다. 오류를 구분하는 방식, snapshot과 재계산, 호출 순서를 숨길 책임 경계의 세 결정을 적고, 각 결정마다 버린 대안 하나와 선택 이유를 남깁니다. W2에서 사용할 기본 장면은 `POST /api/v1/orders/{orderId}/discount`, `couponId` 요청, 주문·원금·할인·최종 금액 응답입니다. 이 외부 모양과 다르게 설계했다면 차이와 이유를 명시합니다.

- [ ]  **전체 회귀와 제품 코드 무변경을 확인한다**

관찰 테스트는 주문 할인 구현을 대신하지 않습니다. 전체 API 테스트를 실행하고 제품 코드가 바뀌지 않았는지 확인합니다.

```bash
./gradlew :apps:commerce-api:test
git diff --name-only -- apps/commerce-api/src/main
```

마지막 명령의 출력은 비어 있어야 합니다.

### 확인 방법

선택한 저장소의 HEAD, 두 테스트 실행, 네 HTTP 결과, 설계 문서의 빈 필드, `src/main` diff를 차례로 확인합니다. 테스트가 0개이거나 skip되거나 exit code가 0이 아니면 통과가 아닙니다.

문서의 구조와 실행 결과를 확인했으니, 설계 선택의 문체가 아니라 출처와 동작을 기준으로 완료를 판단합니다.

### 통과 기준

- [ ]  `git rev-parse HEAD`가 Guide의 Java 또는 Kotlin SHA와 같고, `git diff --name-only -- apps/commerce-api/src/main` 출력이 비어 있다.
- [ ]  Example E2E, `ContractClassificationTest`, 전체 `commerce-api:test`가 테스트 0개와 skip 없이 exit code 0으로 끝난다.
- [ ]  설계 문서에 확인된 사실 2개, 실습 조건 4개, 제품 질문 3~5개가 구분되고 질문마다 바뀌는 동작·데이터·권한 중 하나가 연결된다.
- [ ]  `INV-001..006` 각 행에 출처 구분, 반례 입력, 기대 결과, 책임 후보가 있으며 출처 없는 제안은 보류·거절 또는 해당 없음으로 표시된다.
- [ ]  API·오류·책임 경계의 세 결정마다 버린 대안과 이유가 있고, W2가 사용할 `규칙 ID / 입력 / 기대 결과 / 책임 후보`를 읽을 수 있다.

파일 이름이나 문장 표현만으로 통과하지 않습니다. 반대로 글의 문체나 설득력은 Action Quest에서 기계적으로 채점하지 않습니다.

- 실패 시 단서
    - 테스트가 실행되지 않으면 기존 `ExampleV1ApiE2ETest`의 `RANDOM_PORT`와 `TestRestTemplate` 설정만 비교합니다.
    - 사실과 질문이 섞이면 “이 문장을 제품 담당자나 현재 동작에서 확인할 수 있는가?”부터 묻습니다.
    - 질문이 늘어나면 답이 사용자 응답, 데이터 의미, 권한을 바꾸는 항목만 3~5개로 남깁니다.
